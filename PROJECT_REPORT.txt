1. EXECUTIVE SUMMARY & ARCHITECTURAL OVERVIEW
================================================================================
Kaufee-Home is a production-grade, local-first Autonomous Agentic AI framework 
engineered to solve complex workspace, software development, data transformation, 
and desktop automation tasks with deterministic safety, bounded repair budgets, 
and zero-leak isolation.

The system is decomposed into three cooperating functional modules aligned with 
modern distributed systems theory:
  1. Resource Discovery & Device Manager: Detects host runtime environments, 
     sandboxed execution nodes (Docker containers vs. local subprocesses), external 
     Model Context Protocol (MCP) servers, and hardware resource saturation.
  2. Intelligent Task Scheduler: Employs an autonomous multi-step planner, a 
     Two-Tier Hybrid LLM Router (balancing fast local Ollama inference against high-
     reasoning remote models), preflight risk approval gates, and priority dispatch.
  3. Fault Tolerance & Result Management: Operates an AST-driven syntax and runtime 
     verifier, an automated self-repair loop with bounded retries, atomic snapshot 
     rollbacks, tamper-evident audit logs, and dual monitoring dashboards (Terminal 
     TUI + Web UI).

3. MODULE 1: RESOURCE DISCOVERY & DEVICE MANAGER
================================================================================

3.1 Submodule Breakdown
-----------------------
A. Device & Environment Discovery:
   - File Reference: `src/kaufee/tools/runner_base.py`
   - Dynamically probes the host operating system (Windows NT, Linux/glibc, macOS 
     Darwin).
   - Inquires Docker daemon availability via `docker info`. Specifically checks the 
     daemon operating system mode (`OSType: linux` vs `OSType: windows`). If a 
     Windows container engine is active without Linux manifest compatibility, the 
     system detects the incompatibility and falls back immediately to 
     SubprocessRunner to prevent runtime exit codes (e.g., Docker error 125).
   - Discovers local Model Context Protocol (MCP) server configurations defined in 
     `kaufee_mcp.json` or `.kaufee/mcp/`.

B. Node & Tool Registration:
   - File Reference: `src/kaufee/tools/registry.py`
   - Manages a thread-safe registry of all execution nodes, local filesystem tools, 
     browser automation tools, desktop utilities, and dynamically discovered MCP 
     tools.
   - Generates JSON Schema definitions dynamically for model prompt ingestion and 
     function-calling dispatch.

C. Hardware & System Resource Monitoring:
   - File Reference: `src/kaufee/tools/system.py`
   - `ListProcessesTool` interfaces with `psutil` to dynamically retrieve real-time 
     process tables, tracking:
       * Process Identifier (PID)
       * Process Name
       * Normalized CPU utilization (%)
       * Resident Set Size (RSS) memory utilization (%)
   - `DockerRunner` sets hard kernel resource limits: `--memory 512m` and `--cpus 1.0` 
     to ensure executed agent code cannot cause host starvation.

D. Heartbeat & Health Check Mechanism:
   - File Reference: `src/kaufee/cli.py` (`kaufee doctor`), `src/kaufee/safety/guardrails.py`
   - Employs non-blocking probe intervals to verify local inference node 
     responsiveness (`GET http://localhost:11434/api/tags` with a 2.0s probe 
     timeout).
   - Monitors tool execution health; tracks consecutive execution failures per tool 
     type to activate circuit breaker locks before process escalation occurs.

4. MODULE 2: INTELLIGENT TASK SCHEDULER
================================================================================

4.1 Submodule Breakdown
-----------------------
A. Task Goal Analysis & Planning:
   - File Reference: `src/kaufee/agent/planner.py`
   - Parses unstructured natural language user goals into structured, deterministic, 
     multi-step DAG (Directed Acyclic Graph) plans.
   - Enforces strict JSON Schema serialization:
       {
         "plan": [
           {
             "step_number": 1,
             "description": "...",
             "tool_name": "...",
             "arguments": {...},
             "expected_outcome": "..."
           }
         ]
       }

B. Two-Tier Hybrid Scheduling Algorithm:
   - File Reference: `src/kaufee/llm/router.py`
   - Implements an intelligent routing matrix that balances inference cost, latency, 
     and model capability:
       * Tier 1 (Fast Local Tier): Ollama `qwen2.5-coder:7b` for sub-second, zero-
         cost local workspace queries, file reading, code generation, and low-risk 
         transforms.
       * Tier 2 (High-Reasoning Remote Tier): OpenAI/DeepSeek `gpt-4o-mini` / 
         `deepseek-coder` for complex multi-file architectural reasoning, semantic 
         dependency conflict resolution, and complex failure recoveries.
   - Dynamic Model Switcher automatically falls back to the alternate tier if 
     timeout, network disconnect, or context-length saturation occurs.

C. Load Balancing & Execution Scheduling:
   - File Reference: `src/kaufee/tools/python_runner.py`, `runner_base.py`
   - Dynamically selects between `SubprocessRunner` (low-latency execution) and 
     `DockerRunner` (isolated container sandbox) based on task risk profile and 
     daemon compatibility.
   - Schedules tasks across bounded execution windows (configurable 1-120s timeout, 
     default 15s).

D. Priority & Autonomy Gate Management:
   - File Reference: `src/kaufee/safety/policy.py`, `src/kaufee/safety/grants.py`
   - Evaluates each action against 4 hierarchical Risk Levels:
       * SAFE     : Non-mutating read actions (immediate dispatch)
       * MEDIUM   : Ephemeral operations / clipboard writes (dispatched in assisted)
       * HIGH     : Code execution, process spawns, file writes (approved in assisted)
       * CRITICAL : Shell escapes, protected directory access (`.git`, `.env`) (BLOCKED)
   - Pre-flight plan approval gates display the entire planned sequence to the user 
     upfront, eliminating unexpected downstream actions.
   - Session-scoped grants allow users to approve a specific tool (e.g. `write_file`) 
     for a fixed number of invocations or time window.

5. MODULE 3: FAULT TOLERANCE & RESULT MANAGEMENT
================================================================================

5.1 Submodule Breakdown
-----------------------
A. Failure Detection & AST Verification:
   - File Reference: `src/kaufee/agent/verifier.py`
   - Does not trust LLM self-evaluation. Enforces dual independent postcondition 
     checks:
       1. Static AST Parsing: Evaluates generated Python files via `ast.parse()` to 
          catch `SyntaxError` and `IndentationError` before process execution.
       2. Dynamic Process Diagnostics: Captures return codes, `stderr`, and 
          unhandled exceptions (`ZeroDivisionError`, `ModuleNotFoundError`, etc.).
   - Employs a Circuit Breaker (`src/kaufee/safety/guardrails.py`) that monitors 
     repeating tool arguments; trips after 3 identical consecutive calls to prevent 
     infinite execution loops.

B. Task Reassignment & Autonomous Self-Repair:
   - File Reference: `src/kaufee/agent/controller.py`, `verifier.py`
   - When a step fails verification, the controller does not crash. It enters an 
     autonomous repair routine:
       * Formulates a focused diagnostic prompt containing the exact stack trace, 
         failing line numbers, and file context.
       * Invokes the planner model to produce a targeted corrective step.
       * Enforces a bounded budget (`max_repairs = 3`) to prevent runaway API spend.
   - Atomic Snapshot Rollback: Prior to modifying or deleting any file, the system 
     captures an SHA-256 verified snapshot in `.kaufee/backups/`. If a modification 
     breaks the project, `UndoFileTool` restores the file to its exact prior state.

C. Result Collection & Automated Redaction:
   - File Reference: `src/kaufee/safety/redactor.py`, `src/kaufee/state/models.py`
   - Aggregates all stdout, tool results, file states, and timings into an 
     immutable `TaskState`.
   - Regular expression pattern scanners automatically redact OpenAI/Anthropic/AWS 
     keys, private tokens, passwords, and `.env` credentials from all collected 
     logs and console outputs.

D. Performance & Visualization Dashboards:
   - In-Terminal Dashboard (`kaufee tui` / `dashboard`): Powered by Textual. 
     Renders live step progress, token throughput, tool call logs, and system metrics.
   - Standalone Web UI (`kaufee web` / `ui`): Lightweight embedded HTTP server 
     running on `http://127.0.0.1:8765`. Provides real-time browser-based dashboard 
     cards, task status, execution telemetry, and structured audit log inspectors.

8. RESPONSIBLE AI FRAMEWORK (6 CORE PRINCIPLES IMPLEMENTATION)
================================================================================
Kaufee-Home embeds 6 pillars of Responsible AI directly into the execution engine:

1. Fairness:
   - Deterministic, unbiased policy rules and standard AST/exit-code verifiers 
     evaluate all code strictly against objective postconditions without model-
     favoring bias.
2. Reliability & Safety:
   - AST syntax parsing prior to run, circuit breakers for repetitive tool loops, 
     bounded repair budgets, atomic file operations, and pre-action backup 
     snapshots for instant rollback.
3. Privacy & Security:
   - Strict workspace confinement (blocking path traversal escapes like 
     `../../etc/passwd` or symlink escapes), automatic regex secret redaction in 
     all outputs/logs, and prompt injection filters.
4. Inclusiveness:
   - Plain-English task summaries, dual interfaces (accessible CLI and modern Web UI), 
     clear diagnostic explanations for all blocked actions, and cross-platform 
     support (Windows, Linux, macOS).
5. Transparency:
   - Explicit two-phase planning showing every step before execution, real-time 
     thought/action streaming, and immutable JSON audit logs.
6. Accountability:
   - Human-in-the-loop (HITL) approval gates for destructive and executing actions, 
     configurable autonomy modes (`manual`, `assisted`, `autonomous`), and durable 
     logs recording user approvals.
